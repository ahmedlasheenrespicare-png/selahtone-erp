# نظام صلة تون المالي - مخطط النظام

## 1. المكونات الرئيسية للنظام

### اللوحة الرئيسية (Dashboard):
- المتابعة التنفيذية - تظهر المؤشرات الرئيسية
- الحافظة المالية - مركز المعلومات المالية
- إحصائيات المبيعات - مؤشرات المبيعات والتحليل

### قسم المالية (Finance):
- الحسابات النقدية (Cash Accounts) - إدارة حسابات النقد
- المصروفات (Expenses) - إدارة المصروفات
- التسوية (Settlements) - توثيق الفروق المالية
- التحويلات (Transfers) - إدارة التحويلات

---

## 2. مسار طلب تسوية (Settlement)

**المنفذ:** الموظف (CS_AGENT)

**الخطوات:**
1. عد النقد الفعلي - الموظف يعد كل ما بيدك الآن
2. حساب المتوقع:
   - عهدة الموظف + مبيعات الفترة - مصروفاتها
3. حساب الفرق:
   - المعدود - المتوقع = العجز أو الزيادة
4. تقديم الطلب - حفظ طلب التسوية في قاعدة البيانات

**بيانات التسوية:**
- requestId: معرف الطلب
- accountId: معرف الحساب
- countedAmount: المبلغ المعدود
- expectedBalance: الرصيد المتوقع
- deviation: الفرق (عجز أو زيادة)
- reason: سبب التسوية
- status: الحالة (OPEN/CONFIRMED/REJECTED/CANCELLED)

---

## 3. مسار طلب توريد للخزنة (Custody Request)

**المنفذ:** الموظف يطلب، والمدير/المحاسب يوافق

**الخطوات:**
1. الموظف يطلب عهدة بمبلغ مقترح + سبب
2. المدير/المحاسب يقرر:
   - موافقة + جرد فعلي → يفتح الحساب
   - رفض + مدون → لا يفتح الحساب
3. عند الموافقة:
   - تحديد تاريخ الجرد الفعلي
   - الإقرار بالجرد
   - فتح الحساب للعهدة

**بيانات الحساب النقدي:**
- id: معرف الحساب
- userId: معرف المستخدم
- branchId: معرف الفرع
- openedAt: تاريخ الفتح
- currentBalance: الرصيد الحالي
- status: الحالة (ACTIVE/CLOSED)

---

## 4. أنواع الحسابات النقدية

**عهدة كاونتر (CS_AGENT):**
- فرع واحد فقط
- يعتمد على الفرع المحدد

**عهدة مدير (MANAGER):**
- كل الفروع
- صلاحيات كاملة

**عهدة محاسب (ACCOUNTANT):**
- كل الفروع
- صلاحيات كاملة

**عهدة اليوم (Daily Custody):**
- تفتح في بداية اليوم
- تغلق في نهاية اليوم بالتسوية

## 6. ملخص العلاقات

**المستخدم (CS_AGENT)**
    │
    ├──▶ يطلب عهدة (CustodyRequestForm)
    │       │
    │       ▼
    │   المدير/المحاسب (MANAGER/ACCOUNTANT)
    │       │
    │       ├──▶ يوافق + يجري جرد فعلي → يفتح الحساب
    │       └──▶ يرفض + مدون → لا يفتح الحساب
    │
    ├──▶ يعد النقد + يقدم طلب تسوية (SettlementRequestForm)
    │       │
    │       ▼
    │   يتم حفظ طلب التسوية في قاعدة البيانات
    │
    └──▶ يغلق عهدة (CustodyCloseForm)
            │
            ▼
        يتم إغلاق الحساب وحساب الرصيد النهائي

**المساران الرئيسيان:**
1. تسوية (Settlement) - توثيق الفروق في نهاية الفترة
2. توريد للخزنة (Custody Request) - فتح عهدة نقدية للفرع
