# أصناف البيع وعزل المخزون

تصميم مثبّت بقرار من صاحب العمل (٢٠٢٥-١٠-٣١). يوثّق ما بُني ولماذا، ولا يعرض بدائل مفتوحة.

## ١. لماذا

سير العمل الفعلي في الشركة **لا يستخدم مخزونًا ولا مستودعات**: الموظف يبيع خدمة أو قطعة،
ويتفق مع العميل على السعر، ويسجّله. مسار البيع القديم كان يشترط مستودعًا ورصيدًا وسعرًا
من قاعدة البيانات وضريبة لكل صنف — فكان عائقًا لا ضبطًا.

## ٢. القرارات المثبّتة

| # | القرار |
|---|---|
| ١ | **المخزون والمستودعات معطّلة افتراضيًا**، ولا تُعاد إلا بقرار منفصل ومتغيّر بيئة صريح (`INVENTORY_ENABLED=true`) |
| ٢ | **البيع لا يعتمد على المخزون إطلاقًا**: لا مستودع، لا رصيد، لا سيريال، لا خصم آلي |
| ٣ | **السعر يكتبه الموظف بنفسه** وهو **نهائي** |
| ٤ | **الضريبة «غير محددة»**: تُحفظ فارغة (NULL) لا صفرًا ولا إعفاءً، ولا حساب ولا إقرار تلقائي |
| ٥ | **لكل بند كمية** افتراضها ١ |
| ٦ | **الأصناف تُدار من شاشة للمدير**: إضافة وتعديل وإيقاف فقط، **بلا حذف**، وكل تغيير يُسجَّل بسببه وقبلَه وبعده |

## ٣. شجرة الأصناف (بيانات البداية)

- **بطاريات:** مقاس ١٣ · مقاس ٦٧٥ · مقاس ١٠ · مقاس ٣١٢
- **قوالب:** سوفت · هارد · شل
- **صيانة:** حقول يكتبها الموظف — نوع السماعة · بيان الحالة · بيان الصيانة
- **سماعة:** حقل واحد — نوع السماعة
- **أخرى:** تيوب · إير تيب · فلتر · ماسك · حافظة سماعة · سماعة

التصنيف ذو النوع الواحد يُنتقى تلقائيًا، فيظهر «صيانة» و«سماعة» بحقولهما مباشرة بلا خطوة إضافية.

## ٤. قواعد الحفظ (الخادم فقط)

1. الصنف يُقرأ من قاعدة البيانات في المعاملة نفسها؛ **الموقوف لا يُباع**، وإيقاف تصنيف يوقف أنواعه.
2. الحقول اللازمة يُتحقّق منها على الخادم، و**الحقل غير المعروف يرفض البند** (نموذج قديم أو بيانات مزوّرة).
3. لقطة كاملة في بند الفاتورة: اسم التصنيف والنوع وعناوين الحقول وقيمها كما كتبها الموظف.
4. الخصم يُوزَّع على البنود بنسبة قيمتها (أكبر البواقي)، وحد الموظف محفوظ كما كان.
5. الفاتورة + بنودها + دفعتها الأولى **معاملة واحدة**: كلها أو لا شيء، وتكرار `requestId` إعادة لا تكرار.
6. لا تكرار لنوع في الفاتورة؛ الكمية تُجمع في بند واحد.

## ٥. الفواتير القديمة

تبقى كما سُجّلت: بمستودعها وضريبتها ومنتجاتها. الأعمدة صارت تقبل الفراغ، والفواتير القديمة لم تتغيّر،
والمرتجعات والتحصيلات تعمل عليها كما كانت (لا رصيد مخزون لبنودها إن لم تكن مخزونية).

## ٦. الملفات والفحوص

| المسار | ما هو |
|---|---|
| `prisma/manual-catalog-sales-upgrade.sql` | الترقية اليدوية (إضافة فقط + رفع قيود؛ بلا تعديل بيانات) — **تُشغَّل قبل النشر** |
| `src/lib/catalog-sales.ts` | المحرك: قراءة الشجرة، إنشاء البيع، إدارة الأصناف وسجلّها |
| `src/lib/catalog-validation.ts` | تحقق المدخلات قبل أي وصول لقاعدة البيانات |
| `src/lib/feature-flags.ts` و`src/lib/inventory-gate.ts` | تعطيل المخزون: قائمة + صفحات + إجراءات + واجهة برمجة |
| `src/app/(app)/sales/new` | شاشة البيع الجديدة (والمسار القديم محفوظ في `warehouse-sale.tsx`) |
| `src/app/(app)/sales/catalog` | شاشة إدارة الأصناف للمدير |
| `npm run check:catalog` | ترقية ١/١ + محرك ٦/٦ |

## ٧. ترتيب النشر

**ترقية القاعدة أولًا** (بيد صاحب العمل)، ثم دمج الكود ونشره: الكود يقرأ الجداول والأعمدة الجديدة،
ولن يعمل قبلها. الترقية إضافة فقط، فلا توقف ولا فقدان بيانات.
