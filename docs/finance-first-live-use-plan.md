# خطة أول استخدام فعلي للمالية — نظام جديد

الحالة: **خطة إعداد فقط؛ اختير نشر وقاعدة مستقلين لكل عميل، والتفعيل لكل نسخة يحتاج GO مستقلًا**
السياق الذي وصفه المشغّل في 2026-11-11: النظام جديد، ولم يُجرب على مستخدمين حقيقيين، ومرجع النشر الحالي غير معروف له. النقد الفعلي صفر برواية المشغّل؛ الموظف يعدّ والمدير والمحاسب يراجعان؛ أُنشئ مدير ومحاسب وموظف؛ الـadmin يراقب التشغيل.
المسار المختار: A — تفعيل العلم فقط، بلا SQL أو أدوار أو نشر كود، مع الرجوع إلى `false` عند المشكلة.

> **قرار العزل:** اختار المشغّل **نشرًا وقاعدة مستقلين لكل عميل**. لا توجد حاجة الآن إلى بناء نشر مشترك multi-tenant. كل نسخة عميل لها خدمة وقاعدة وأسرار اتصال وجلسات ومستخدمون ونسخ احتياطية ومراقبة مستقلة. لا تُشارك قاعدة أو أسرار أو حسابات مستخدمين بين العملاء. كل نسخة تبدأ بـ`FINANCE_ENABLED=false` وتحتاج قرار GO خاصًا بها.

## قواعد لا تُتجاوز

- لا يُفترض أن النقد صفر لأن النظام جديد. كل رصيد افتتاحي يأتي من عدّ فعلي، وصفر فقط إذا كان النقد الفعلي صفرًا.
- كون النظام بلا مستخدمين سابقين لا يثبت خلو الجداول أو صحة الإعدادات القديمة؛ لا تُحذف أي صفوف ولا تُعاد تهيئة القاعدة.
- لا SQL أو `db:push` أو `seed` أو ملفات test-only. لا تغيير لخطة A إلا بقرار جديد يحولها إلى مسار B.
- لا عمليات مالية تجريبية بأموال حقيقية. أول عملية تكون لغرض تجاري حقيقي ومراجعتها البشرية موثقة.

## المرحلة 1 — التعيين والمراجعة قبل العلم

1. يحدد المشغّل المدير والمحاسب المسؤولين عن أول تشغيل، ومن سيعدّ النقد ومن سيراجع العد.
2. تراجع أسماء المستخدمين وحالة `ACTIVE` وأدوارهم وفروعهم. اختيار «الجميع» لا يعني تجاوز مستخدم موقوف أو دور غير صحيح.
3. يراجع المشغّل أن الخدمة الحالية ما زالت `FINANCE_ENABLED=false` وأن `/finance` محوّل، وأنه لا توجد ترقية أو تغيير أدوار أو كود متزامن.
4. يسجل مرجع النشر من Render إن أمكن. عدم معرفته لا يُختلق؛ يلزم تحديد الخدمة والنشر الجاري وصفيًا قبل التغيير حتى لا يُعدّل بيئة أخرى.
5. يحدد المشغّل من سيراقب أول تشغيل، وقناة الإبلاغ، وقرار النسخ الاحتياطي الحالي. لا تُطلب روابط أو أسرار في المحضر.

**توقف إذا كان هناك شك في الخدمة أو البيئة أو الأدوار.**

## المرحلة 2 — الجرد الفعلي قبل فتح الحسابات

لكل خزنة فرع وعهدة موظف ستُستخدم:

- اسم الحساب/الفرع والموظف المسؤول، دون إنشاء حساب وهمي.
- المبلغ الفعلي المعدود، بما فيه الصفر إن كان حقيقيًا.
- تاريخ ووقت العد، ومن عدّ ومن راجع.
- لا توجد مبالغ «افتراضية» ولا حساب يفتح قبل اكتمال هذا السجل.

يمكن إجراء العد قبل تفعيل العلم، ثم إدخال الرصيد بعده. إذا تغير النقد بين العد والإدخال يعاد الجرد.

## المرحلة 3 — قرار GO المستقل

لا يبدأ إلا بعد المرحلتين السابقتين. القرار يجب أن يحدد صراحةً تفعيل `FINANCE_ENABLED=true` في الخدمة المقصودة ضمن المسار A. دمج PR أو مناقشة الخطة أو عبارة «أعده للاستخدام» ليست هذا القرار.

عند التنفيذ المستقل من المشغّل:

1. تثبيت أن القيمة قبل التغيير `false`.
2. تغيير العلم فقط إلى `true`، دون Blueprint Sync أو SQL أو تعديل أدوار.
3. تسجيل الوقت والمشغّل والنشر الناتج.
4. انتظار اكتمال النشر والتحقق من توفر المالية، ثم فتح الحسابات بالجرد الفعلي.
5. عند فشل غير مفهوم: إعادة `false` وعدم تكرار العمليات عمياء.

## المرحلة 4 — بدء تدريجي رغم نطاق «الجميع»

- يبدأ المدير/المحاسب بفتح الحسابات ومراجعة الأرصدة الظاهرة قبل عمل الموظفين.
- لا يبدأ موظف بعهدة لم تُفتح وتُراجع.
- أول تحصيل أو مصروف أو تحويل يكون فعليًا وموثقًا، ثم تراجع نتيجته والحركة والرصيد قبل التوسع.
- الرد النقدي مسموح بقرار المشغّل، لكنه ليس أول اختبار مقترح. عند وجود رد تجاري حقيقي فقط: حساب صحيح، ومرجع جرد حديث، ومراجعة الرصيد، وقرار بشري موثق. لا رد بلا هذه الشروط ولا رد تجريبي.
- يراجع المشغّل الأخطاء والطلبات مرفوضة النتيجة وأي نتيجة COMMIT مجهولة قبل أي إعادة طلب.

## الرجوع

عند مشكلة: إعادة `FINANCE_ENABLED=false` وفق قرار المشغّل، دون حذف حركات أو Sync. توثق الوقت والسبب والنشر الناتج. الرجوع لا يمحو حركة ملتزمة ولا يعيد نقدًا ماديًا ولا يثبت استعادة قاعدة. تُراجع الطلبات مجهولة النتيجة قبل استئناف العمل.

## قائمة نسخة كل عميل

1. تحديد خدمة العميل وقاعدته المستقلة وصفيًا، والتأكد أن النسخة لا تشير إلى قاعدة عميل آخر؛ لا تُسجل الأسرار في Git أو المحاضر.
2. إنشاء مدير ومحاسب وموظف خاصين بالعميل، ومراجعة حالة `ACTIVE` والأدوار والفروع. المستخدمون المذكورون في النسخة الحالية لا يُعدون مستخدمين لنسخة أخرى تلقائيًا.
3. بدء `FINANCE_ENABLED=false`، ثم التحقق من تحويل `/finance` والنشر المطلوب.
4. توثيق عدّ النقد الفعلي لكل خزنة وعهدة: الموظف يعدّ، والمدير والمحاسب يراجعان. صفر صحيح فقط للنقد الفعلي الصفري في تلك النسخة.
5. تحديد قرار النسخ الاحتياطي وفترة مراقبة الـadmin، ثم قرار GO مستقل لتلك النسخة فقط.
6. بعد GO: فتح الحسابات بالجرد، ثم بدء تدريجي ومراجعة أول عملية تجارية حقيقية.

## ما لم يُحسم بعد

- وقت العد والحسابات المشمولة في أول نسخة؛ المبلغ الحالي صفر برواية المشغّل.
- تحقق فعلي من حالة وصلاحيات المستخدمين الثلاثة في كل نسخة.
- قرار النسخ الحالي وفترة المراقبة؛ الـadmin هو مالك المراقبة.
- تحديد خدمة وقاعدة أول عميل ومرجع نشرهما وصفيًا.
- قرار GO مستقل صريح لكل نسخة.

**لذلك تبقى الحالة WAIT والقيمة false.**
