> **قابل للتنفيذ فورًا، بلا أي SQL إنتاجي الآن.** آخر حالة مؤكدة: القيمة الفعلية
> `false` في العملية الشغّالة (بطاقة `/setup`)، و`render.yaml:31` ما زال `"true"`،
> والحكم `IDENTITY_GAP_CONFIRMED` / `NOT_READY`. لا ترقية مطلوبة: مخطط `finance`
> موجود بـ18 كائنًا. **المالية غير جاهزة للنشر.**
>
> قاعدة ذهبية: **كل مرحلة لها بوابة موافقة، ولا تُفتح التالية قبل إغلاق سابقتها.**
> الإجازة الحالية محصورة في *فحص قراءة فقط من اتصال التطبيق المجمّع*؛ أي توسيع
> يحتاج: نصًا مُراجَعًا ← موافقة SQL صريحة منفصلة ← خطة رجوع ← موافقة نشر منفصلة.

## ٢. الخطوات بالتفصيل

### المرحلة ٠ — التثبيت (أنت، دقيقتان، بلا أي SQL)
1. **اترك `FINANCE_ENABLED=false`** كما هو. لا تُعده `true` «لإنجاز المهمة»؛ المهمة لا تتطلبه،
   وإعادته تُعيد فتح الواجهة تحت `neondb_owner` ب`bypass_rls=true`.
2. **لا تضغط `Sync` / `Update` / `Manual Deploy`** في `dashboard.render.com/blueprints`؛
   `render.yaml:31` يُعلن `"true"` وأي مزامنة تُعيد تطبيقها.
3. **سجّل وأرسل لي ثلاث معلومات فقط**: التاريخ/السنة الحقيقية لسجل النشر (`Nov 10` بلا سنة)،
   مَن ضبط القيمة `false`، وبأي قرار/موافقة. لا تُرسل قيم اتصال أو كلمات مرور.
4. **لا تُنفّذ أي SQL الآن** في SQL Editor. اتركه مفتوحًا بلا `Run`.

### المرحلة ١ — إغلاق `C3` (**أُنجزت**؛ أنت، قراءة فقط، بالإجازة الحالية)
5. على **جهاز موثوق**، وبنفس الرابط المجمّع (`DATABASE_URL`) لكن من **اتصال ثانٍ**، شغّل
   الملف المحمول: `prototypes/finance-app-identity/install-and-run-on-mac.sh` يفكّ
   `probe-payload.b64` إلى `~/finance-probe`، يثبّت `pg@8`، ويقرأ الرابط ب`read -r -s`
   بلا طباعة، ثم ينفّذ `app-identity-probe-standalone.mjs` ببوابة
   `FINANCE_IDENTITY_PROBE_CONFIRM="I reviewed the SQL"`. التفاصيل في
   `docs/finance-app-connection-access-ar.md` §٦.
6. أرسل **عمود `app_connection_probe` فقط** — لا روابط، لا أخطاء السائق، لا بيانات صفوف.
7. **أنا أنفّذ فورًا**: `node prototypes/finance-app-identity/evaluate-app-connection-probe.mjs --file <العمود>`
   ثم أُحدّث الحكم والوثائق والحراس. **النتيجة الفعلية:** التقريران متماثلان حرفيًا
   (`whole_aggregate_identical=true`)، فصار `C3=PASS` عبر `--compare`، وبقي
   `C1/C2=FAIL` و`NOT_READY`. لم يختلف `current_user`، فلا شرط إيقاف. **المرحلة التالية
   الآن هي ٢** (جرد مسبق قراءة-only بعد مراجعة النص وموافقة صريحة).

> لا تُشغَّل أداة الفحص في SQL Editor ولا بـ`DIRECT_URL`؛ هي لاتصال التطبيق المجمّع فقط.

### المرحلة ٢ — الجرد المسبق (**أُنجزت / STOP مُلغى بقرار صريح**؛ أنت، قراءة only)
8. افتح الملحق «أ» أدناه و**اقرأ النص فقط**. لا تُنفّذه بعد.
9. قل لي صراحةً: «راجعتُ نص الجرد وأُجيز تشغيله قراءةً فقط». عندها فقط يُصبح مصرّحًا به.
10. نفّذه في SQL Editor داخل `BEGIN TRANSACTION READ ONLY … ROLLBACK`، وأرسل النتيجة
    **بلا اسم قاعدة ولا رابط اتصال**. الغرض: معرفة `current_user` في المحرر، عضوياته،
    وملاك كائنات `finance` وحجم `public` المطلوب منحه لأي دور جديد.
11. **مطابقة 18 كائنًا بملكية `neondb_owner`** هي دليل الارتباط بنفس القاعدة التي فُحصت،
    دون كشف اسمها. إن ظهر دور مختلف أو عدد مختلف ⇒ **توقف** ولا يُنقل أي شيء.
    **ما حدث فعلًا:** أعاد الاستعلام ٤ الرقم `80` لأنه يعدّ كل `pg_class`
    (18 جدولًا + 15 تتابعًا + 47 فهرسًا)، ف**شرط التوقف تحقق**. التسوية أوفلاين أثبتت
    تطابق أسماء الجداول الـ18 و`owned_by_neondb_owner=80` وغياب `request_results`
    ⇒ لا انحراف مخطط. **وقُبل التوقف صراحةً** بعبارة المشغّل «نعم اقبل اكمل
    الخطوات سريعا» (§٣٧): أُغلق STOP واستُؤنفت المرحلة ٣. هذا القبول **ليس**
    موافقة SQL ولا موافقة نشر ولا إعادة `true`.

### المرحلة ٣ — مسودة تغيير الأدوار (**أُنجزت مخبريًا**؛ أنا)
12. أُعدّ `prototypes/finance-app-identity/role-change-DRAFT-NOT-EXECUTABLE.md`:
    دور تطبيق منفصل بلا عضويات شاملة وبلا `BYPASSRLS`، منح انتقائي على `finance`
    **وعلى كل `public` وتتابعاته**، نقل ملكية الـ18 كائنًا إلى دور إدارة، خطة رجوع،
    وترتيب تنفيذ. **لا SQL قابل للتنفيذ، ولا جدول، ولا بصمة ترقية جديدة، ولا `request_results`.**
13. **أُنجزت:** `role-change-DRAFT-NOT-EXECUTABLE.md` فيه الأرقام الفعلية

14. نفّذ الدفعة في SQL Editor，**وخطة الرجوع مكتوبة بجانبك**: إنشاء الدور ← المنح ←
    نقل الملكية ← التحقق. أي فشل ⇒ `ROLLBACK` فورًا وإبلاغي قبل إعادة المحاولة.
15. أرسل **ملخصًا وصفيًا فقط** (نجاح/فشل، عدد الكائنات، اسم الدور الجديد). لا أسرار.
16. **لا تُدوّر الدور القديم قبل نجاح المرحلة ٥**؛ فهو وسيلة الرجوع الوحيدة.

### المرحلة ٥ — تغيير `DATABASE_URL` (أنت، بموافقة نشر منفصلة)
17. غيّر `DATABASE_URL` في Render إلى الدور الجديد، **وضع `FINANCE_ENABLED` يبقى `false`**.
18. في الخطوة نفسها وبموافقة منفصلة: صحّح `render.yaml:31` إلى `"false"` لإزالة التعارض
    المعكوس (تغيير ملف + نشر، لا تلمسه قبل ذلك).
19. تحقق: `/login` (فحص الصحة)، `/setup`، وصفحة غير مالية مثل `/sales`. إن تعطّل أي
    مسار ⇒ **الرجوع فورًا إلى `DATABASE_URL` القديم**؛ لأن الدور الجديد إن لم يُمنح
    صلاحيات `public` يتعطل التطبيق كله لا المالية وحدها.

### المرحلة ٦ — `C4` / `C5` وما بعد التشغيل (الطرفان)
20. إعادة فحص الهوية **من داخل الخدمة**، ثم اختبارات RLS والمحفّزات التسعة عشر بأدوار
    حقيقية، ثم فحص ما بعد التشغيل. تبقى `C4`/`C5` خطوتين منفصلتين.
21. عندها فقط يُعرض **قرار منفصل** بشأن إعادة `FINANCE_ENABLED=true` بشروط
    `docs/finance-release-log.md` §٢٤ كاملة. ليس ضمن هذا المحضر.

## أ. ملحق — مسودة استعلام الجرد (⚠️ **DRAFT للمراجعة فقط، غير مُجاز للتنفيذ الآن**)

> **لا تُلصق هذا النص في SQL Editor قبل الخطوة ٩.** هو قراءة-only داخل معاملة
> تُنهى ب`ROLLBACK`، ولا يقرأ صفوف عمل، ولا يطبع اسم قاعدة أو مضيف أو رابط،
> ولا يُنشئ أي كائن. لكنه **ليس ضمن الإجازة الحالية** ويحتاج موافقتك الصريحة.
**توقع النتيجة (مُضاف بعد ورودها، والنص أدناه لم يتغيّر):** الاستعلام ٤ يعدّ **كل**
صفوف `pg_class` في `finance` لا الجداول وحدها، فالعدد المتوقع **80** (18 `r` +
15 `S` + 47 `i`) لا 18؛ والاستعلام ٣ يُظهر الجداول الـ18 ب`kind='r'`. هذا بالضبط
ما ورد، وهو **لا انحراف مخطط** لكنه يُفعّل شرط التوقف في الخطوة ١١. لا يُصحَّح
النص المُراجَع بأثر رجعي؛ أي تعديل يستوجب مراجعة وموافقة جديدتين.

**اختُبرت نحويًا** على PostgreSQL 18 محلي مؤقت بلا أي اتصال إنتاجي: 8 عبارات
(`BEGIN` + `SET LOCAL` + 5 `SELECT` + `ROLLBACK`) نُفذت بلا أخطاء؛ والقيم صفر في
القاعدة الفارغة كما هو متوقع. الاختبار الآلي `check:finance:preflight-draft` يمنع
انحراف النص إلى أي كتابة أو كشف اسم قاعدة/رابط.

```sql
-- DRAFT / NOT AUTHORIZED FOR EXECUTION / reviewed text required first
BEGIN TRANSACTION READ ONLY;
SET LOCAL statement_timeout = '15s';

-- ١) هوية الدور داخل SQL Editor (قد يختلف عن دور التطبيق)
SELECT current_user::text AS editor_current_user,
       session_user::text AS editor_session_user,
       (SELECT rolsuper      FROM pg_roles WHERE rolname = current_user) AS editor_superuser,
       (SELECT rolbypassrls  FROM pg_roles WHERE rolname = current_user) AS editor_bypass_rls,
       (SELECT rolcreatedb   FROM pg_roles WHERE rolname = current_user) AS editor_create_db,
       (SELECT rolcreaterole FROM pg_roles WHERE rolname = current_user) AS editor_create_role;

-- ٢) العضويات الموروثة (وهل يمكن سحبها)
SELECT r.rolname AS inherited_role, m.admin_option AS has_admin_option
FROM pg_auth_members m JOIN pg_roles r ON r.oid = m.roleid
WHERE m.member = (SELECT oid FROM pg_roles WHERE rolname = current_user)
ORDER BY r.rolname;

-- ٣) جرد كائنات finance: المالك وحالة RLS
SELECT c.relname AS object_name, c.relkind AS kind,
       pg_get_userbyid(c.relowner) AS owner, c.relrowsecurity AS rls_enabled
FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'finance'
ORDER BY c.relname;

-- ٤) ارتباط بنتيجة الفحص السابقة بلا كشف اسم القاعدة
SELECT count(*)::int AS finance_object_count,
       count(*) FILTER (WHERE pg_get_userbyid(c.relowner) = 'neondb_owner')::int AS owned_by_neondb_owner,
       count(*) FILTER (WHERE c.relrowsecurity)::int AS rls_enabled_objects
FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'finance';

-- ٥) حجم ما يحتاج منحًا عند تغيير DATABASE_URL
SELECT count(*)::int AS public_relation_count
FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public' AND c.relkind IN ('r','p','v','m','S');

ROLLBACK;
```
