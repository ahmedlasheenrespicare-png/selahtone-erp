# المالية داخل التطبيق — مرحلة منقولة ومعطّلة افتراضيًا

هذا المجلد هو نقل نواة المالية من معمل `prototypes/finance-engine` إلى التطبيق الحقيقي، **مرحليًا وبمفتاح تعطيل**. تُحجب واجهات المالية وعملياتها عند تعطيل `FINANCE_ENABLED`؛ ولا نفترض إعداد بيئة فعلية أو جاهزيتها. قد يفحص دليل المستخدمين وجود العهد لحماية تغيير الحالة أو الفرع حتى مع تعطيل الواجهة.

## ما نُقل حتى الآن

- `engine.ts`: النواة بعد تحويلها من `finance_lab` إلى المخطط المراجَع `finance`، مع استخدام الجداول الحقيقية `public.users` و`public.branches` و`public.expense_categories` (مع تحويل الأنواع `role_code::text` و`status::text`). مُنفذ البنود `tx.categoryPort` صار **إلزاميًا** للإنشاء والتعديل بدل الكتابة المباشرة.
- `request-result-link.ts`: مسودة مخبرية تربط كل أمر `command()` بصف نتيجته عبر `finance.request_results` داخل المعاملة، وتفحص الرابط في replay و`23505`؛ الطلب القديم بلا رابط يُرفض صراحة. تحتاج ملف SQL المراجَع قبل أي تشغيل فعلي، ولم تُطبَّق ترقية على قاعدة أعمال؛ التفاصيل في `docs/finance-request-result-link-ar.md`.
- `types.ts` و`validation.ts` و`policy.ts` و`categories.ts` و`app-categories.ts`: منقولة كما هي مع توافق المسارات. صار `categories.ts::run()` يحفظ ويفحص `finance.request_results` لنفسي إجراءَي `CREATE`/`EDIT` عبر `candidateCategoryPort(tx)`، بنفس السياسة الصارمة؛ التفاصيل في `docs/finance-request-result-link-ar.md`.
- `db.ts`: معاملة `SERIALIZABLE` واحدة من عميل Prisma الحقيقي، وتحويل أخطاء السائق، وإعادة التحقق من الجلسة مقابل صف المستخدم داخل المعاملة (`assertFinanceActor`)، ومفتاح `FINANCE_ENABLED`.
- `session-transaction.ts`: فحص دور المستخدم وفرعه وبريده ونشاطه وتغيير كلمة مروره، ثم قفل جلسة الجهاز والتحقق من صلاحيتها داخل معاملات أكشنات المالية، بما فيها replay وإعادة المحاولة. يفحص الانتهاء بعد القفل ولا يضمن بقاء الجلسة صالحة حتى لحظة الالتزام؛ لا يجعل قواعد `access_control` ذرية مع العملية.
- `src/app/(app)/finance/page.tsx`: صفحة أولى تعرض الحسابات المسموحة فقط. **عند تعطيل المالية تُحوّل إلى `/dashboard` ولا تُنفَّذ أي استعلام مالي.**
- عنصر قائمة جديد يظهر فقط عند تشغيل المالية.

## ما لم يُنقل بعد

واجهة المصروفات الكاملة واعتمادها وصرفها، واجهات الجرد والتاريخي وحالات الاشتباه، وربط البيع والتحصيل والرد بالحركات النقدية، وتقارير الموظف. كل بند يُنقل على مرحلة مع اختباره.

## شرط التشغيل (لم يتحقق بعد)

1. ترقية SQL مراجَعة تُنفَّذ على قاعدة الإنتاج، وفحص ما قبلها وما بعدها متطابقان.
2. الصلاحيات وRLS وهوية دور التطبيق قبل فتح الواجهة. **المرفقات ملغاة نهائيًا بقرار 2026-10-30: لا مرفقات ولا تخزين ملفات في النظام.**
3. نسخة حديثة واختبار استعادة.
4. موافقة تشغيل الترقية، ثم موافقة نشر منفصلة، ثم ضبط `FINANCE_ENABLED` ومراقبة ما بعد التشغيل.

## الاختبارات

```bash
npm run check:finance:app-engine   # النواة المنقولة على المخطط المراجَع بجداول حقيقية وهمية
npm run check:finance:release-candidate
```

الأول يثبت أن النواة المنقولة تعمل على المخطط المراجَع مع `public.users` و`public.branches` و`public.expense_categories`، وأن العمليات المالية لا تلمس الصفوف القديمة ولا تُنشئ مخطط المعمل. لا يثبت صلاحيات الإنتاج أو أن الترقية نُفذت.
