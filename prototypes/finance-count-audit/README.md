# Synthetic cash-count evidence inventory (test only)

`audit.test-only.ts` reads one synthetic branch in the caller's transaction; it never writes, repairs, or executes on app startup. It lists each count and checks whether the linked count adjustment is compatible with status, account, branch, sign and amount. An audit event containing `bookBalance` is only **evidence that a field was recorded**, not proof of its semantics, accuracy, provenance or chronology. Absence is not proof of an error. A matching movement is not proof that a count, source data, settlement, timestamps or account attribution were correct. Awaiting holder is not a validated zero count. The tool requires the reviewed candidate schema and `manual-custody-and-count-requests.sql` in a disposable test database; it is not a production runbook, migration, backfill, or remediation recommendation.

Historical investigation and correction require a separately reviewed plan, verified supporting records, authorization, access controls and a consistent snapshot. Do not infer the balance expected at the historical count from today's period totals. No SQL in this directory should be run against production data.
