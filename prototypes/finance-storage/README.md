# نموذج أولي لبروتوكول مرفقات Neon — للاختبار فقط

اختار المستخدم **Neon Object Storage الخاص**، على أن يُتحقق من توفره في مشروعه ومن حدود خطته. الخدمة تجريبية (Beta)، ولا نفترض أنها مفعّلة. لا يوجد هنا اتصال بـNeon أو مفتاح أو حاوية أو مسار إنتاج؛ لا تنسخ النموذج كما هو للتطبيق. النسخ الجديدة واختبار الاستعادة ما زالا مؤجلين بقرار المستخدم.

## المنجز والمختبر

`chunk-protocol.ts` يحتوي فقط على قواعد محلية مستقلة: تقسيم الملف (حتى 5,000,000 بايت) إلى أجزاء لا تزيد على 512,000 بايت، وقراءة محدودة بالعدد والوقت لا تثق بـ`Content-Length`، ورفض الترميز غير المتوقع والبيانات الناقصة أو الزائدة، وتجميع الأجزاء والتحقق من الامتداد والتوقيع وSHA-256، والتحقق من سلامة أجزاء التنزيل. لا ينجز أي مصادقة أو تفويض أو تخزين أو ضمان تزامن؛ نجاح اختباراته لا يثبت صلاحية رفع/تنزيل عبر Netlify أو Neon. توقيع الملف ليس فحص برمجيات خبيثة.

الاختبار المعزول: `npm run check:finance:storage`. بعد تعديل فحص الميتاداتا شغّل أيضًا `npm run check:finance:engine` و`npm run check:finance:app` واختبارات متصفح المرفقات. اختبارات المعمل المعتادة ما زالت تستخدم تخزينًا وهميًا في قاعدة ذاكرة، وليس Neon Object Storage.

## التصميم المرشح قبل التنفيذ

لتجنب طلب ملف كامل يتجاوز حد Netlify المخزّن، وبدون رابط رفع عام، يتواصل المتصفح مع التطبيق نفسه فقط بأجزاء صغيرة، والخادم وحده يتواصل مع حاوية Neon **خاصة**. هذا اختيار هندسي مرشح، لا بروتوكول إنتاج مكتمل:

1. يبدأ المدير أو المحاسب عملية مرفق واحد لمصروف موجود، بعد فحص الجلسة والدور من الخادم والتحقق من الاسم والنوع والحجم المعلن. يُنشأ طلب ذو هوية عشوائية وربط بالمصروف وبالمُدخل، مع مهلة وحصص معقولة للجلسات والبايتات المؤقتة. لا تُقبل جلسة ثانية متعارضة للمصروف نفسه، ولا تؤثر المحاولة الفاشلة في المصروف أو النقد.
2. تُرسل الأجزاء بحد ثابت أقل من حد Netlify. على كل طلب التحقق مجددًا من الجلسة والصلاحية والفرع وحماية CSRF، والترتيب/العدد والحجم الفعلي؛ يحفظ تكرار الجزء نفسه مرة واحدة، ويرفض طلب الهوية نفسها بمحتوى مختلف. مسار تجميعي محتمل هو حفظ الأجزاء **مؤقتًا** في PostgreSQL بحصة ومدة قصوى، لذا يجب حساب أثره على مساحة قاعدة الخطة المجانية وتنظيفها. لا تُحجز مساحة بلا حد.
3. بعد اكتمال الأجزاء، يعيد الخادم تجميع نسخة ثابتة، ويتحقق من الحجم والتوقيع والتجزئة، ثم يرفعها بحساب الخادم إلى مفتاح نهائي عشوائي خاص. المتصفح لا يحصل على حق كتابة ذلك المفتاح؛ هذا يتجنب إمكان إعادة استعمال رابط رفع بعد التحقق. المفتاح ليس رابطًا عامًا.
4. لا توجد معاملة واحدة تشمل PostgreSQL وتخزين الكائنات؛ لا ندعي الذرية بينهما. يلزم تصميم **حالة قابلة للاستئناف** مع قفل/مهلة محاولة وهوية ثابتة، وحفظ سجل التدقيق ومرجع الملف بحركة قاعدة ذرية بعد نجاح الرفع، واختبارات السقوط عند كل فاصل. يجب منع محاولة قديمة من اعتماد ملف بعد إلغاء العملية أو استرداد مهلة قفلها. لا يُعرض المرفق إلا بعد اكتمال واعتماد البيانات.
5. يُنزّل المدير أو المحاسب الأجزاء عبر مسار من التطبيق، مع إعادة تفويض كل طلب والتحقق من طول الجزء وتجزئته المحفوظة، ثم تُجمع وتُتحقق تجزئة الملف قبل تنزيله. لا يُكشف مفتاح الحاوية أو سرها للمتصفح، ولا يلزم جعل الحاوية عامة. يجب ضبط `no-store`، و`nosniff` و`Content-Disposition: attachment` لمنع العرض غير المقصود؛ واختبار وصول الموظف غير المصرح به بالطلبات المباشرة، لا بالواجهة فقط.
6. فشل الشبكة أو قاعدة البيانات قد يترك ملفًا يتيمًا، ومحاولة قديمة قد تصل بعد عملية تنظيف. يلزم فحص دوري متأنٍ بحواجز زمنية وقفل، ومقارنة المفاتيح بالمرجع الموثوق قبل الحذف، مع إعادة الفحص لاحقًا. **Neon Beta لا يفرض حاليًا lifecycle أو versioning**؛ لا نعتمد عليهما للتنظيف أو الاستعادة. لا يُحذف ملف مشار إليه أو تُحذف نسخة المستخدم القديمة بسبب مهمة صيانة.
7. `pg_dump` لا يضم كائنات Neon Object Storage. يلزم تصميم نسخ مستقل للمرفقات ومطابقته بالبيانات قبل أي ادعاء بإمكانية الاستعادة؛ لا يُنفّذ النسخ أو اختبار الاستعادة ما دام مؤجلًا. حدود التخزين والنقل المجاني قابلة للتغيير، وقد يتوقف الرفع أو الخدمة عند بلوغها؛ لا نفترض مساحة أو نقلًا لا نهائيين.

## ما زال مطلوبًا قبل الإنتاج

- تنفيذ نموذج التخزين الفعلي وحالة الطلبات على قاعدة معزولة، مع اختبار انقطاع الاتصال، فشل الكتابة والتدقيق والنسخ إلى الحاوية، إعادة المحاولة، تضارب المستخدمين والمهلات والتنظيف المتأخر.
- اختبار تنزيل الأجزاء ودمجها، إبطال الصلاحية بين جزء وآخر، أسماء الملفات الضارة، تغيير أو اختفاء كائن مخزن، واكتمال الملفات الكبيرة؛ تحقق المتصفح وNetlify الفعلي يجب أن يكون في بيئة تجريبية مستقلة بعد إذن منفصل.
- التحقق من توافر الخدمة والمنطقة، وطريقة منح صلاحية محدودة وإعداد سرّ الخادم دون كشفه، وخطة مراقبة السعة والنسخ، ثم مراجعة أي تغيير على Neon أو Netlify مع المستخدم قبل تنفيذه.
